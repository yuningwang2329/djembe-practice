# 简谱式歌词、双横线与轻击回归修复

## 本轮纠正的方向

上一轮保住了录音时间，但把歌词退回整句均匀排列、整句高亮，损失了用户已经认可的简谱阅读体验。本轮恢复“歌词尽量对齐鼓点字母，连续扫色和进度与竖线同步”。既有录音拍点、365 句句首/句尾与歌词文本不改，不回滚到旧的错位时间表。

## 原因及修复

1. **歌词失去简谱式对位**：音符与歌词原来用了不同的布局坐标。现在共用音符时值格、小节边框及变拍宽度；单字居中，多字分配在对应格内；拥挤处仅做最小局部避让。扫色裁切边界、歌词进度末端与竖线使用同一百分比，并做横竖屏像素检查。
2. **双横线重叠/断裂**：第一层画在音符组、第二层画在各个字上，底部基准不同。改为同一容器内两个固定层，间隔 3 px；连续十六分音符共享第二层线段，八分音符不加第二层。
3. **点击鼓点首音可能漏播**：媒体时钟在首次调度前推进 12 ms 的复现测试中，旧调度器把被点的 b 当作过去事件跳过。现在在 play 前记住起点，容许补发 60 ms 内未调度音符，按真实速度换算；不补发跳转点之前的音、不重复播放已安排音、不追赶长时间挂起的旧音。
4. **b 额外变闷**：原 b 除 0.70 力度外另用 260 Hz 低通，B 为 360 Hz。真实采样渲染表明实际 RMS 比值约 0.609，而不是 0.70。现在 B/b 使用同一 1200 Hz 低通，保留可听起音，b 仅靠力度变轻；回退合成器同样保持 B/b 过滤一致。实际采样输出回归验证 0.70 比例、非静音、无单音削顶、起音差小于 5 ms。**旧 b 并非所有场景都绝对无声；真机扬声器和伴奏掩蔽仍需听感确认。**
5. **避免每帧重画全曲**：稳定传给行组件的点击回调，保留最新行为，避免播放器每帧更新使所有离屏歌词行重画。

## 查阅并复用的本地资源

- 只查阅此项目对应的 Claude Code 会话（`6bc452ea-201c-4262-ad27-acded959a540`）及项目 Git 历史，没有把其他项目聊天当材料。
- 已有 HTDemucs 分离人声、中文 wav2vec2 CTC 模型、Whisper small 和 `/tmp/whisperenv` 可用；没有下载新模型、调用收费接口或上传音频。
- 旧 `chars.py` 的 onset/DP/均匀插值与真正 CTC 不同；历史聊天里的“CTC 精确”“已对齐”不是独立证据。本轮复用带人声指纹的顺序 CTC 候选，不直接恢复旧 `lyricCharTimes`。
- 新打包工具核对原 MP3 和人声轨指纹，保留重复字的出现位置。共 3250 字：1922 字沿用通过局部筛选的模型候选，1328 字在有效邻近锚点/句边界之间估计。低分/挤压/错字情况在 `lyric-layout-audit.json` 保留，**不能称 3250 字均已精确识别**。
- 排字锚点只决定歌词放在哪个音符格，视觉扫色使用用户指定的提前竖线；不反向改写 MP3、鼓点或真实句子起止。

## 回归要求

已执行并通过：143 项单元/组件测试、37 项浏览器测试、5 项 Python 算法测试、TypeScript 检查和生产构建。浏览器测试覆盖首音点击、轻击真实采样渲染、歌词不丢不重复、十首横竖屏无文字碰撞、双横线几何、扫色与竖线误差小于 1 px，以及十首本地真实 MP3 的变速和离线重开。另核对本轮 10 份文件指纹、365 句文本与句首/句尾全部未变。

这些结果不代替真实 iPad 扬声器听感，也不把模型候选或插值当作逐字精准认证。
