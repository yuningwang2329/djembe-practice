# 同步修复交付报告（2026-09-19）

十首真实录音已完成本地自动校准、句级时间表接入及软件回归。**这不是逐字精准同步认证，也不是 iPad 人工听感验收。** 下面明确列出修复、证据与剩余边界。

## 已确认的软件问题

- 歌词组件拿竖线位置决定逐字变色，没有使用传入的演唱时刻。已经改成读取演唱时间。
- App 的“画面提前量”会同时提前音符放大、歌词和竖线。现在只传给竖线/视窗，鼓音放大和歌词仍读取实际录音时间。
- 播放时钟在 `audio.currentTime` 停滞时用墙钟外推，可能将声音时间向前推。已移除外推，主时钟只读取音频元素。
- 旧强制对齐脚本按 token ID 建立位置字典，同字多次出现会覆盖前一次。新增本地候选工具按字符出现顺序保存；旧逐字数据不能因此被视为已修好。
- 一句刚开唱但第一个字排到下一行时，会短暂没有任何歌词高亮。现在以句子边界驱动首/尾显示片段，跨行不再延迟高亮。
- 十首歌使用同一份录音级时间表，不再叠加旧的速度校正和歌词偏移；真实录音与视觉提前量各自独立。
- 本地导入增加 SHA-256 核对。不同文件只提示，不删除、不禁止播放；转码也会改变指纹，所以提示不等于断定音频版本有错。

**用户明确要求保留视觉提前**：0.48 拍基础提前量不变，另保留界面可调提前量。竖线经过音符中心不再作为音频对齐的验收条件。

- 这些播放测点检查的是网页进度与真实媒体时钟差值小于 120 ms，**不是歌声/鼓声人工听感误差测量**。

## 仍需明确的验收边界

- 未进行逐首人工听感验收，也无法代替家人的真实 iPad/蓝牙设备验证；没有宣称全曲每个字或鼓点都已达到约 100 ms。
- 模型低分、自由演唱、稀疏钢琴段仍有不确定性。已经保留具体句号和时刻，后续反馈可以直接定位，不再整首反复推倒重排。
- 本次保留原编配与手序，不是重新逐小节审核所有教材转录。网站更新不删除 iPad 已导入歌曲。
