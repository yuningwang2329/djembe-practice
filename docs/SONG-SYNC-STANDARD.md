# 新歌接入与同步验收规范

本文件是今后同步修改的统一要求。用户在同一聊天中提供录音、鼓谱图片，最好附带同版本 LRC，即可开始。不要要求用户重述播放器功能；不要用“测试通过”代替录音同步验收。

## 三条时间线，不能混用

1. **实际声音**：唯一依据是当前录音的 `audio.currentTime`。鼓点使用该录音绝对毫秒；不能额外叠加已计入数据的前奏偏移，不能在音频停顿时凭墙钟继续前进。
2. **歌词**：独立的录音起止时间，不依附第几小节。歌词提前/滞后只改歌词；不准为了把词塞进谱子而增删鼓谱小节。
3. **视觉竖线与歌词扫色**：以 2026-09-20 最新反馈为准：**B 击响放大时，竖线正好在 B 中心**，取代此前主动提前 0.48 拍的要求。四分、八分、十六分音符均按实际渲染格中心建立位置锚点，锚点时间使用原有击响时间，锚点间连续插值，跨小节不瞬移。默认额外提前量为 0，不继承旧版提前设置；用户仍可手动微调。进度用文字扫色表示，与鼓谱竖线共用横坐标，**歌词下方不再画水平进度线或第二根短竖线**。视觉投影不许改写演唱时间、鼓声调度或点击跳转，也不等于逐字声学识别结果。浏览器回归必须在实际击响时刻测量字母和竖线中心，误差小于 1.5 CSS 像素，不能再以“相差不足半拍”为通过条件。

## 必须保留的练谱体验（2026-09-19 用户再次确认）

- 像简谱一样，歌词尽量放在相应鼓点字母下方，单字居中，多字围绕该音符居中分配；不能为了同步修复退回整句随意均分。
- 有可信的逐字候选就用于选择对应音符格；低分、错字、挤压和缺词局部降级并记录。句子时间仍独立于记谱格。
- 当前行歌词从左到右连续扫色，与鼓谱竖线齐头前进；离开当前行后恢复普通木色，不让唱过的整屏歌词一直亮橙色。歌词区不加尺线或折角。保留三小节一行、缓慢跟随、后续行预读、点谱跳转。
- 十六分音符两条横线必须有清楚间距；连续十六分的第二横线连成一段，不能逐字画成断裂或挤在同一条线上。
- 小写 b/s 是轻击，不是休止；要测真实音频输出和点击首音，不能只测 gain 被赋值。B/b 的力度区别不能靠把 b 的可听起音滤掉。
- 同步/识别工具升级前，逐项对照这些体验，并在横竖屏实际渲染里验收；时间表通过不代表呈现方式可以任意替换。

## 接收和转录

- 保存录音 SHA-256、原文件名、解码时长、歌手和版本。不同演唱/剪辑版本不得复用同一时间表；标题和相近时长不能证明版本相同。
- 商业录音仅保留本地和用户 iPad，不提交 Git，不上传第三方分析服务。没有授权不另找网络版本替换。
- 按原谱逐段展开重复、休止、弱起、变拍和加花。保留 B/T/S、R/L；小写 b/t/s 表示轻击，不等同左手。没有手序时明确记录采用的规则。
- 原谱不清楚之处单独列出，不凭歌词长度推算应有的小节数量。

## 鼓点校准

- 先判别：固定偏移、累积速度漂移、局部变速、半拍/整拍错相、结构错误、录音版本不同，不能统一用一个 offset 修复。
- 测首个可靠拍点和 BPM；至少用前、中、后三段独立确认。不能只在旧 BPM ±2 的范围找到峰值就宣布正确。
- 稳定录音采用稳定网格加稀疏锚点；变速录音保存逐拍时间。细分音在相邻拍点间插值，不把全小节一概拉伸，也不逐小节取整累加误差。
- 看低频强拍和高频节奏的对应关系，避免追逐更响的反拍。留出未参与拟合的拍点做检查；峰值接近只证明节奏周期吻合，不证明谱子重音、拍号和段落已经正确。

## 歌词校准

- 第一优先级是句子出现/高亮与人声对应。逐字效果是额外能力，不用伪造逐字精度换取“看似卡拉 OK”。
- LRC 是参考，不是自动真值。对齐必须使用这份录音；重复主副歌按出现顺序匹配。
- CTC 的字符按**出现位置**保存，不按 token ID 建字典；同一字在一句内多次出现必须有不同记录。输入按模型要求归一化。
- 模型缺字、低分、边界碰撞、字符挤在同一时刻、整句过短、首字落进上一句等必须拦截。记录原输出、采用值、方法、失败原因。
- 插值、LRC 退回和人工估计必须标为估计；不能称为“声学实测/精准逐字”。低置信度句子进入复核清单，不以自动脚本无异常作为通过。
- 词在屏幕上尽量按相应鼓点位置排开；局部避让只能改变画面，不能反过来改变演唱时间。跨行不能丢字、重复、增加省略号。

## 必须交付的验收材料

每首歌独立出一行状态和详细证据：录音指纹、拍点模型、首/中/尾锚点、修正前后偏差、歌词总句数、估计/待复核句清单、谱面结构变更来源。

**验收分四级，不能混称：**

- 数据检查：时间单调、范围合法、字符和句子没有丢失、没有越界鼓点。
- 自动声学检查：记录样本数及误差分布，标明稀疏伴奏和弱证据段；不能据此宣称人工听感通过。
- 听感复核：每首开头/中间/结尾、每次段落切换和所有异常句；原曲与示范鼓声一起播放，至少 1×、0.75×。目标明显拍点偏差不超过约 100 ms，句首不超过约 300 ms；不满足则继续修或注明未通过。
- 真机验收：iPad 横屏、耳机/扬声器分别检查，导入正确版本，播放/暂停/拖动/小节循环/变速/后台恢复/离线重开。蓝牙延迟单独诊断，不反向污染歌曲数据。

没有听到的段落必须写“未完成人工听感验收”，没有真机必须写“未完成真机验收”。不能保证浏览器测试通过就全部对齐。

## 修改与发布纪律

- 保留稳定 song ID 和本地导入音频，不因为代码更新清掉 IndexedDB。
- 一首歌一次变更，保留对比和回退数据。不把低置信度批处理结果自动覆盖全部曲目。
- 新规范优先于旧脚本里的“已验证”“精确”等注释；旧注释不是证据。
- 运行单元/组件测试、类型检查、构建、浏览器实际预览。更新完成后确认站点版本，用户没刷新不能当作已经体验新版。
- 报告必须分开写：已修复的软件缺陷、已采用的歌曲校准、仍待复核的句子/段落。提交/部署成功不等于同步验收成功。

## 本地工具

`scripts/export-sync.test.ts` 用 `SYNC_EXPORT` 导出当前曲库；`audit-recordings.py` 生成音频指纹和节奏诊断；`track-recording-beats.py --work <诊断目录>` 生成候选拍点；`align-recording-lyrics.py --out <诊断目录>` 使用已缓存的本地模型生成有来源标记的歌词候选。

这些工具不上传录音。候选结果必须经过上述质量门禁和复核，禁止自动当成发布批准。

### 当前版本的落地流程

当前网站采用**按鼓点排字、与竖线一致的连续扫色**。正式数据为 `recordingGrids.json`（拍点）和 `recordingLyrics.json`（句子 + 排字候选），按录音指纹关联。`layoutTimesMs` 只用于选择谱面格子，不伪称逐字听感验收；`layoutTiming` 区分 CTC 候选与混合估计，逐字拒绝原因/分数见 `lyric-layout-audit.json`。旧 `lyricCharTimes` 不再用于这十首歌曲的正式显示。

1. 接收素材后登记录音及原谱，完成原谱转录与节奏诊断。`audit-recordings.py`、`track-recording-beats.py` 生成拍点候选。
2. 使用已缓存的本地中文模型运行 `align-whole-recording.py --work <诊断目录>`；Apple GPU 可加 `--device mps`。整首顺序匹配避免围着错误 LRC 时间硬切片。
3. 用 `constrain-lyric-candidates.py --work <诊断目录>` 检查宽松句子窗口。必须先检查 LRC 漏句、重复次数和时间明显错误，不能拿旧窗口强迫录音服从。
4. 异常句使用重复段落、局部 ASR、人声音量边界交叉检查。确需修订的边界写入 `scripts/lyric-boundary-overrides.json`，注明文本、时刻、来源和估计性质；不要把规则藏进播放器。
5. `package-recording-grids.py --work <目录> --output src/data/recordingGrids.json --report docs/recording-beat-audit.json`；`package-recording-lyrics.py --work <目录> --output src/data/recordingLyrics.json --report docs/recording-lyric-audit.json`。打包歌词时重新核对原文件 SHA-256；换录音后必须重做，不得复用缓存。
   随后运行 `package-lyric-layout.py --work <目录> --output src/data/recordingLyrics.json --report docs/lyric-layout-audit.json`。再次核对 MP3 和人声轨指纹；按字符出现位置匹配，筛掉低分/坍缩/越界候选，仅在邻近有效锚点之间估计。不得重用按字 ID 建立的旧位置字典。
6. 运行 `npm run test:run`、`npm run build`、`npx playwright test`。本地额外运行 `LOCAL_AUDIO_DIR=../raw npx playwright test e2e/recording-sync.spec.ts`，使用原 MP3 检查首中尾、变速和离线重开。CI 不持有这些商业音频。
7. 人工听感与真机验收另外记录。模型低分不自动等于错位，但必须留在报告里；浏览器时钟误差也不等于音乐听感误差。

新歌提供“歌 + 谱 + 可选 LRC”即可。首次缺少本地模型/依赖时说明下载需求；不要求用户申请付费 API，不上传录音。
